# 套餐与计费模块设计文档

> 版本：v3.0（2026-08-10）
> 范围：Go Kratos 后端（admin / user）、管理员后台（Ant Design Pro）、企业工作台（Next.js userconsole）
> 目标：在现有 `ent_plans / ent_subscriptions / ent_quota_limits / ent_usage_ledgers` 基础上，补齐订单、点数、计费规则、统一计费服务，形成"套餐购买 → 双账本扣费 → 到期/耗尽拦截"的完整闭环。
> 关系：本文档是 `后续设计方向.md §3` 的细化与增强版，落地实施以本文档为准。

---

## 1. 概述

### 1.1 设计目标

1. **一张订单表驱动所有交易**：开通 / 续费 / 加购 / 充值 / 退款五类交易统一用 `ent_subscription_orders` 承载，用 `order_type` 区分，不拆多张表。
2. **额度与点数双账本独立流转**：周期性资源走额度账本（`ent_quota_limits`），按次付费的 AI 能力走点数账本（`ent_points_balances`），互不混用。
3. **计费规则配置化**：12 项点数单价存 `cfg_system_settings`，管理员后台可改，不改代码。
4. **未实现业务预留接口**：7 项未实现的业务动作通过"计费项注册表"机制预留，后续实现时只需挂接业务逻辑，计费链路不动。
5. **套餐体系对齐细软产品版本**：三大类（普通行业版 / 特殊行业版 / 定制版）共 8 个预置套餐，支持半年付 + 年付两种定价周期，预置种子数据可在管理员端灵活修改。
6. **遵守项目硬约束**：GORM AutoMigrate 生产禁用（所有新表走迁移文件）、表前缀按业务域（`ent_` / `cfg_`）、三层模型 DTO（proto）↔ DO（biz）↔ PO（data）。

### 1.2 设计原则

| 原则 | 说明 |
|---|---|
| 订单驱动 | 一切交易（开通/续费/加购/充值/退款）都生成订单记录，便于对账与审计 |
| 双账本隔离 | 额度随套餐周期重置；点数是消耗性钱包，不重置；二者独立对账 |
| 点数不清零 | 到期后点数冻结但不清零，续费后恢复使用；续费时旧余额保留，新赠送点数叠加 |
| 毫点存储 | 点数用 BIGINT 存毫点（1 点 = 1000 毫点），避免浮点误差，与金额用分存储思路一致 |
| 配置即规则 | 计费单价、套餐价格、功能开关全部入库可配置，不硬编码 |
| 预留可扩展 | 未实现业务通过注册表占位，计费链路与业务实现解耦 |
| 种子可改 | 预置套餐种子数据仅为初始化模板，管理员可在套餐管理页面任意增删改 |

### 1.3 相对 v2.0 的三处关键变更

1. **定价周期改造**：取消月付（monthly），改为半年付（half_yearly）+ 年付（yearly）。数据库字段 `monthly_price_minor_units` 重命名为 `half_yearly_price_minor_units`，半年付有效期 180 天（6×30 天），年付有效期 365 天。
2. **PlanMetric 枚举扩展**：新增 4 项关键词配额指标（品牌词数 / 产品核心词数 / 客户指定词条数 / AI 衍生长尾词数），对齐细软产品版本的核心指标体系。
3. **预置细软套餐种子数据**：新增迁移 `000042_seed_geo_plans.up.sql`，预置 8 个细软标准套餐（普通行业版 3 档 + 特殊行业版 4 档 + 定制版 1 档）及其配额限制与功能开关。

## 3. 核心概念：三账户模型

企业开通套餐后，同时拥有**三个独立账户**，互不影响。这是理解整个模块的关键。

### 3.1 三账户定义

| 账户 | 存储表 | 性质 | 重置规则 | 用途 |
|---|---|---|---|---|
| **有效期**（时间账户） | `ent_subscriptions.expires_at` | 时间窗口 | 续费时顺延 | 控制能否使用系统 |
| **额度**（Quota 账户） | `ent_quota_limits` | 周期性计数 | 每月/每年重置 | 周期性资源（文章数/发布数/查询数/关键词数） |
| **点数**（积分账户） | `ent_points_balances` | 消耗性钱包 | 不重置，用完要充值 | 按次付费的 AI 能力 |

### 3.2 三账户关系（关键规则）

- **有效期过期** → 一切停止（即使有额度有点数也不能用）
- **有效期内，额度用完** → 周期性动作被拦截（创作/发布/查询），等下个周期重置或加购
- **有效期内，点数用完** → 按次付费动作被拦截（AI 诊断/指数查询），要充值点数
- **到期后点数不清零**：点数冻结但保留，续费后恢复使用
- **续费时旧点数保留**：新套餐赠送点数叠加到旧余额上

### 3.3 双账本扣费三种模式

| 模式 | 扣额度 | 扣点数 | 示例 |
|---|---|---|---|
| **双扣** | ✓ | ✓ | 创作文章（扣 article_generations + 1 点） |
| **只扣额度** | ✓ | ✗ | 投稿发布（扣 publish_tasks，免费） |
| **只扣点数** | ✗ | ✓ | AI 诊断（扣 10 点，不占周期额度） |

## 4. 数据模型设计

### 4.1 `ent_plans` 商业字段（已落地）

在现有 [ent_plans](file:///d:/geo/kratos-svr/internal/data/model/enterprise.go) 基础上的商业字段：

```sql
ALTER TABLE ent_plans
  ADD COLUMN description VARCHAR(1024) AFTER name,
  ADD COLUMN half_yearly_price_minor_units BIGINT NOT NULL DEFAULT 0,
  ADD COLUMN yearly_price_minor_units  BIGINT NOT NULL DEFAULT 0,
  ADD COLUMN currency CHAR(3) NOT NULL DEFAULT 'CNY',
  ADD COLUMN billing_cycle VARCHAR(32) NOT NULL DEFAULT 'yearly',
  ADD COLUMN visible_to_enterprise BOOLEAN NOT NULL DEFAULT TRUE,
  ADD COLUMN sort_order INT NOT NULL DEFAULT 0,
  ADD COLUMN series_code VARCHAR(64) NOT NULL DEFAULT '',
  ADD COLUMN granted_points BIGINT NOT NULL DEFAULT 0;
```

字段说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| `description` | VARCHAR(1024) | 套餐描述，企业工作台展示 |
| `half_yearly_price_minor_units` | BIGINT | 半年价（分），避免浮点误差 |
| `yearly_price_minor_units` | BIGINT | 年价（分） |
| `currency` | CHAR(3) | 货币代码，默认 CNY |
| `billing_cycle` | VARCHAR(32) | 计费周期：half_yearly / yearly |
| `visible_to_enterprise` | BOOLEAN | 是否在企业工作台"购买套餐"列表显示 |
| `sort_order` | INT | 排序权重 |
| `series_code` | VARCHAR(64) | 系列分组：standard / special / custom；行业变体为同 series 下的独立 plan |
| `granted_points` | BIGINT | 开通/续费时一次性赠送的点数（毫点） |

**设计要点**：
- 一个 plan = 一个可售 SKU（含定价 + 额度 + 功能开关 + 赠送点数）
- 行业变体（旅游版 / 教育版 / 医疗版等）= 同 `series_code` 下的独立 plan，各自定价，**不引入"行业加价规则表"**
- `visible_to_enterprise=true` 的套餐才在企业工作台"购买套餐"列表显示
- 金额用最小单位（分）存 BIGINT，点数用毫点存 BIGINT，避免浮点误差
- 定价周期仅支持半年付（half_yearly）和年付（yearly），无月付

### 4.2 `ent_subscription_orders` 订单表（已落地）

统一订单表，承载五类交易：

```sql
CREATE TABLE ent_subscription_orders (
  id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  order_no VARCHAR(64) NOT NULL,
  enterprise_id BIGINT UNSIGNED NOT NULL,
  plan_id BIGINT UNSIGNED,
  order_type VARCHAR(32) NOT NULL,
  cycle VARCHAR(32),
  amount_minor_units BIGINT NOT NULL DEFAULT 0,
  currency CHAR(3) NOT NULL DEFAULT 'CNY',
  credits_amount BIGINT,
  addon_quota_metric VARCHAR(64),
  addon_quota_amount BIGINT,
  renew_from_subscription_id BIGINT UNSIGNED,
  refund_reference_order_id BIGINT UNSIGNED,
  points_before BIGINT,
  points_after BIGINT,
  status VARCHAR(32) NOT NULL,
  source VARCHAR(32) NOT NULL,
  paid_at DATETIME(6),
  approved_at DATETIME(6),
  approved_by BIGINT UNSIGNED,
  remark TEXT,
  created_at DATETIME(6) NOT NULL,
  updated_at DATETIME(6) NOT NULL,
  deleted_at DATETIME(6),
  PRIMARY KEY (id),
  UNIQUE KEY uk_order_no (order_no),
  KEY idx_orders_enterprise (enterprise_id, status, created_at),
  KEY idx_orders_refund (refund_reference_order_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

字段说明：

| 字段 | 说明 |
|---|---|
| `order_no` | 订单号，格式 `ENT-yyyymmdd-序号`，全局唯一 |
| `order_type` | 订单类型：`plan` / `renew` / `addon` / `credits` / `refund` |
| `cycle` | 计费周期：half_yearly / yearly（plan / renew 时有效） |
| `amount_minor_units` | 订单金额（分） |
| `credits_amount` | 充值点数（毫点），`order_type=credits` 时有效 |
| `addon_quota_metric` | 加购的额度指标，`order_type=addon` 时有效 |
| `addon_quota_amount` | 加购额度数量，`order_type=addon` 时有效 |
| `renew_from_subscription_id` | 续费关联的原订阅 ID，`order_type=renew` 时有效 |
| `refund_reference_order_id` | 退款关联的原订单 ID，`order_type=refund` 时有效 |
| `points_before` / `points_after` | 退款前后的点数余额，用于对账 |
| `status` | 订单状态：`pending` / `paid` / `approved` / `cancelled` / `refunded` |
| `source` | 来源：`enterprise_self`（企业自购）/ `admin_grant`（管理员开通） |

### 4.2.1 五类订单的语义与副作用

| order_type | 触发场景 | approved 时的副作用 | 写哪些表 |
|---|---|---|---|
| `plan` | 企业自购 / 管理员开通 | 新建订阅 + 初始化额度 + 发放赠送点数 | `ent_subscriptions` + `ent_quota_limits` + `ent_points_balances` + `ent_points_ledgers` |
| `renew` | 续费 | 延长 expires_at + 重置周期额度 + 发放新套餐赠送点数（旧点数保留） | `ent_subscriptions` + `ent_quota_limits` + `ent_points_balances` + `ent_points_ledgers` |
| `addon` | 加购额外单量 | 增加指定 metric 的 limit_value | `ent_quota_limits` + `ent_usage_ledgers` |
| `credits` | 点数钱包充值 | 增加点数余额 | `ent_points_balances` + `ent_points_ledgers` |
| `refund` | 退款 | 扣减 balance 或回退 limit_value，关联原订单 | `ent_points_balances` + `ent_points_ledgers`（记 before/after） |

### 4.3 `ent_points_balances` 点数余额表（已落地）

```sql
CREATE TABLE ent_points_balances (
  id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  enterprise_id BIGINT UNSIGNED NOT NULL,
  balance BIGINT NOT NULL DEFAULT 0,
  frozen BIGINT NOT NULL DEFAULT 0,
  version BIGINT UNSIGNED NOT NULL DEFAULT 1,
  created_at DATETIME(6) NOT NULL,
  updated_at DATETIME(6) NOT NULL,
  PRIMARY KEY (id),
  UNIQUE KEY uk_ent_points_balance_enterprise (enterprise_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

字段说明：

| 字段 | 说明 |
|---|---|
| `balance` | 可用点数（毫点） |
| `frozen` | 预扣冻结点数（毫点），Reserve 时增加，Settle/Rollback 时减少 |
| `version` | 乐观锁版本号，配合 `SELECT FOR UPDATE` 防并发 |

余额与流水分离：`ent_points_balances` 用于快速校验；`ent_points_ledgers` 用于对账。

### 4.4 `ent_points_ledgers` 点数流水表（已落地）

```sql
CREATE TABLE ent_points_ledgers (
  id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  enterprise_id BIGINT UNSIGNED NOT NULL,
  operation VARCHAR(32) NOT NULL,
  amount BIGINT NOT NULL,
  balance_after BIGINT NOT NULL,
  frozen_after BIGINT NOT NULL,
  reference_type VARCHAR(64),
  reference_id BIGINT UNSIGNED,
  reason VARCHAR(256),
  operator_id BIGINT UNSIGNED,
  idempotency_key VARCHAR(128),
  created_at DATETIME(6) NOT NULL,
  PRIMARY KEY (id),
  UNIQUE KEY uk_points_ledger_idem (idempotency_key),
  KEY idx_points_ledger_enterprise (enterprise_id, created_at),
  KEY idx_points_ledger_ref (reference_type, reference_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

字段说明：

| 字段 | 说明 |
|---|---|
| `operation` | 操作类型：`grant`（赠送）/ `recharge`（充值）/ `reserve`（预扣）/ `settle`（扣减）/ `rollback`（回滚）/ `refund`（退款扣减）/ `adjust`（管理员调整） |
| `amount` | 变动数量（毫点），正数为增加，负数为减少 |
| `balance_after` | 操作后余额快照 |
| `frozen_after` | 操作后冻结快照 |
| `reference_type` | 关联类型：`order` / `subscription` / `publish_task` / `geo_task` / `article_generation` / `keyword_distillation` 等 |
| `reference_id` | 关联 ID |
| `idempotency_key` | 幂等键，防重复扣减 |

## 7. 订单与状态机

### 7.1 订单状态机

```
pending ──确认到账──> approved ──退款──> refunded
   │                    │
   └──取消──> cancelled  └──(approved 副作用见 §4.2.1)
```

- **企业自购** → `pending` → 运营确认到账 → `approved`（避免企业自助绕过收费）
- **管理员开通** → 直接 `approved`（管理员代客户操作，写审计日志）
- **取消**：`pending` 可取消 → `cancelled`
- **退款**：从已 `approved` 订单反向发起 `refund` 订单 → `refunded`，关联原订单

### 7.2 订单号生成规则

格式：`ENT-yyyymmdd-序号`，例如 `ENT-20260810-000123`。

实现：当日序号由 Redis INCR 或数据库序列生成，保证全局唯一。

### 7.3 订单审批流程

| 来源 | 初始状态 | 审批 | 副作用触发 |
|---|---|---|---|
| `enterprise_self` 企业自购 | `pending` | 运营点"确认到账" | `pending → approved`，执行副作用 |
| `admin_grant` 管理员开通 | `approved` | 无需审批 | 直接执行副作用，写审计日志 |

### 7.4 续费时间计算

```
续费时：
  if 原订阅未过期 (expires_at > now):
      new_expires_at = expires_at + 新周期
  else:
      new_expires_at = now + 新周期
  额度重置：used_value=0, reserved_value=0（保留 limit_value）
  点数：balance += 新套餐.granted_points（旧余额保留）
```

### 7.5 定价周期与有效期

| 周期 | cycle 取值 | 有效期 | 说明 |
|---|---|---|---|
| 半年付 | `half_yearly` | 180 天（6×30 天） | 入门版/旅游版/ToC餐饮版/教育版支持 |
| 年付 | `yearly` | 365 天 | 所有版本支持 |

有效期计算位于 [billing_tx.go](file:///d:/geo/kratos-svr/app/admin/internal/data/billing_tx.go)：
- 半年付：`6 * 30 * 24 * time.Hour` = 180 天
- 年付：`365 * 24 * time.Hour` = 365 天

## 8. BillingService 统一计费服务

### 8.1 接口定义

BillingService 是 biz 层内部服务，由各业务 usecase 调用，不直接暴露给前端：

```go
package biz

type BillingService interface {
    // Estimate 估算成本（不扣减）
    Estimate(ctx context.Context, enterpriseID uint64, action string, quantity int64) (*ChargeCost, error)
    // Reserve 预扣冻结（额度 + 点数）
    Reserve(ctx context.Context, cmd ReserveCommand) (reservationID string, err error)
    // Settle 成功扣减（预留转已用）
    Settle(ctx context.Context, reservationID string) error
    // Rollback 失败回滚（解冻归还）
    Rollback(ctx context.Context, reservationID string) error
}

type ChargeCost struct {
    Action       string  // 计费项
    Quantity     int64   // 数量
    PointsCost   int64   // 点数成本（毫点）
    QuotaMetric  string  // 额度指标
    QuotaCost    int64   // 额度成本
    ChargeType   string  // both / quota_only / points_only
    Sufficient   bool    // 余额是否充足
    Reason       string  // 不充足时的原因
}

type ReserveCommand struct {
    EnterpriseID   uint64
    Action         string  // 计费项 key
    Quantity       int64
    ReferenceType  string  // publish_task / geo_task / article_generation / keyword_distillation
    ReferenceID    uint64
    IdempotencyKey string
}
```

### 8.2 执行流程

```
业务动作
   ↓
Estimate 估算（读额度 + 点数 + 单价规则）
   ↓
套餐有效? 余额充足? ──否──> 拦截弹窗（过期/耗尽）
   ↓是
Reserve 预扣（双账本 FOR UPDATE 锁定，写 reserve 流水）
   ↓
执行业务
   ├─成功→ Settle（扣减 used/balance，写 settle 流水）
   └─失败→ Rollback（解冻 frozen，写 rollback 流水）
```

### 8.3 实现要点

- **Estimate** 同时读 `ent_quota_limits`（额度）与 `ent_points_balances`（点数）+ `cfg_system_settings` 单价，返回预估成本
- **Reserve** 用 `SELECT ... FOR UPDATE` 锁两本账：
  - 额度写 `ent_usage_ledgers(operation=reserve)`，增加 `reserved_value`
  - 点数写 `ent_points_ledgers(operation=reserve)`，增加 `frozen`
- **Settle** 扣减 `used_value` / 减少 `balance` 与 `frozen`，写 settle 流水
- **Rollback** 归还 `frozen`，写 rollback 流水
- **idempotency_key** 防重复扣减（复用现有字段）
- **reservation_id** 用于关联 Reserve 与 Settle/Rollback，可存入 `reference_type=reservation, reference_id=xxx`

### 8.4 settle/release 闭环

在 [worker_execution.go](file:///d:/geo/kratos-svr/app/admin/internal/data/worker_execution.go) 任务终态转移处补 settle/release 钩子：

| 任务终态 | 操作 | 流水 |
|---|---|---|
| `succeeded` | Settle：reserved_value 转入 used_value，点数 frozen 转扣 balance | `operation=settle` |
| `failed` | Rollback：归还 reserved_value 与 frozen | `operation=rollback` |
| `cancelled` | Rollback：归还 reserved_value 与 frozen | `operation=rollback` |

## 10. 基础设施补齐方案

### 10.1 settle/release 闭环（已落地）

**问题**：原有 reserveQuota 只 reserve 不 settle，reserved_value 单调膨胀。

**方案**：在 [worker_execution.go](file:///d:/geo/kratos-svr/app/admin/internal/data/worker_execution.go) 任务终态转移处补钩子。

**实现**：
1. `settleQuota(tx, enterpriseID, metric, amount, reservationID)` 函数：`reserved_value -= amount; used_value += amount`，写 `UsageLedger{Operation:"settle"}`
2. `releaseQuota(tx, enterpriseID, metric, amount, reservationID)` 函数：`reserved_value -= amount`，写 `UsageLedger{Operation:"rollback"}`
3. 点数同理：`settlePoints` / `rollbackPoints`

### 10.2 plan_limits → quota_limits 种子化（已落地）

**问题**：订阅生效时不自动初始化 quota_limits，需人工配置。

**方案**：在订单 `approved` 副作用中，从 `ent_plan_limits` 读取该 plan 的所有 metric，批量 upsert 到 `ent_quota_limits`。

**实现**：
```go
func seedQuotaLimits(tx, enterpriseID, planID) {
    limits := planLimitRepo.ListByPlan(planID)
    for _, l := range limits {
        metricStr := PlanMetricToQuotaString[l.Metric]
        quotaLimitRepo.Upsert(tx, enterpriseID, metricStr, l.LimitValue, l.Period)
    }
}
```

### 10.3 到期判定 Cron（已落地）

**触发时机**：每日午夜 00:05 执行。

**逻辑**（[billing_scheduler.go](file:///d:/geo/kratos-svr/app/admin/internal/data/billing_scheduler.go)）：
1. `ExpireOverdueSubscriptions`：扫描 `ent_subscriptions WHERE status='active' AND expires_at < NOW() AND expired_at_processed=FALSE`，更新 `status='expired'`，`expired_at_processed=TRUE`
2. `ResetDueQuotaLimits`：按 period 重置到期的周期性额度（used_value=0, reserved_value=0）
3. `CancelTimeoutOrders`：取消超时未确认的 pending 订单

点数余额在订阅过期时保留（不清零），仅状态变更。

```
任何计费操作前：
  1. 检查 profile.subscription_status
     - expired → 横幅提示"服务有效期已过，请续费" + [立即续费]
     - 点数耗尽 → 横幅提示"点数余额已耗尽，请充值" + [去充值]

  3. 都通过 → 调用 API
```

横幅在计费相关页面（套餐与用量/可购套餐/我的订单）不重复显示。
