## 1. 概述

### 1.1 设计目标

1. **报表分层**：基础报表（现有 `/console/dashboard-data`，全部套餐可见）+ 高级报表（全局数据报表，仅最高级套餐「定制版」可见）。
2. **高级报表多页化**：参考盘古 BrandBoard，高级报表不是单页大报表，而是 **4 + 1 个独立路由页面**（品牌看板 / 优化记录 / 信源分析 / 竞品分析 / 周月报），各页面独立 chunk、独立数据接口。
3. **套餐驱动 gating**：复用现有 `ent_plan_features` 机制（当前未做任何业务 gating），新增 `PlanFeatureAdvancedReport = 6`，绑定定制版，在 user 服务新增 feature 校验。
4. **页面级权限区分**：新增 `ent_page_grants` 表，支持按 plan / role / enterprise 三档控制页面可见性，区分企业客户与交付人员视图。
5. **不污染现有报表**：基础报表（`dashboard-data`）零改动，高级报表独立 service + 独立页面，共享底层聚合工具函数。

### 1.2 与现有 `dashboard-data` 的关系

| 维度 | 基础报表 dashboard-data | 高级报表 brand-board |
|---|---|---|
| 视角 | 企业自有收录数据（单租户） | 跨平台全局视角 + 竞品对比 |
| 接口 | `GetGeoDashboard` 单接口聚合 6 块 | 独立 `GeoBrandBoardService` 多接口分块 |
| 实时性 | SSE 实时推送 + 手动刷新 | 部分离线聚合（周月报/竞品）+ 部分实时 |
| 套餐 | 全部已开通套餐 | 仅定制版（feature=6） |
| 页面数 | 1 页 | 4 + 1 页（独立路由） |
| 数据隔离 | 单企业 | 竞品分析需跨企业（受控） |

### 1.3 设计原则

| 原则 | 说明 |
|---|---|
| 分页不合并 | 不同视角/职责的报表拆独立路由，避免单接口臃肿、便于 feature gating |
| 复用底层 | 时区分桶、SSE 推送、趋势补零等工具函数复用，不重复造轮子 |
| 数据隔离 | 竞品分析跨企业查询须受控，service 层做租户校验 |
| 配置即规则 | 报表可见性走 `ent_page_grants` + 套餐 feature，不硬编码 |
| 表前缀 | 新表统一 `geo_` 前缀（同域 `geo_answer_snapshots` 等），权限表用 `ent_` 前缀 |
| 迁移先行 | 新表走迁移文件（`cmd/migrate`），生产禁 GORM AutoMigrate |

### 3.2 模块1 · 品牌看板（仪表盘式）

**子 tab**：品牌GEO大盘 | 周报 | 月报 | 诊断记录

**布局**（已对齐有数据客户 id=415 真实视觉）：
- 顶部 4 统计卡：关键词量 / 词条量 / 收录总量 / 文章发布总量
- 品牌推荐度（当日数据，7 平台进度条：DeepSeek/豆包/腾讯元宝/文心助手/千问/知乎/微信）
- 数据大盘 5 指标：品牌可见度 / 品牌TOP3 / 正向情感 / 提及次数 / 对话轮次
- 3 个 ECharts 趋势折线（canvas 308×240px）：总收录 / 品牌可见度 / 提及次数，各带 [近7天|本月|今年]
- 情感倾向分析表（3 档：无/正/负，含收录量+占比列）
- 舆情分析（周结/月结切换 + "暂无舆情分析"空态）

**指标定义**（我们实现版本，**不做加权评分**，区别于盘古）：

| 指标 | 定义 | 数据源 | 上限 |
|---|---|---|---|
| 品牌可见度 | `count(brand_mentioned=true) / count(总回答) × 100%` | [analysis_results.brand_mentioned](file:///d:/geo/kratos-svr/internal/data/model/geo_monitor.go#L115) | 100% |
| 品牌TOP3 | brand_mentioned 且排名≤3 的回答占比 | analysis_results + 排名字段 | 100% |
| 正向情感 | `positive / 总提及 × 100%` | [geo_mentions.sentiment](file:///d:/geo/kratos-svr/internal/data/model/geo_monitor.go#L101) | 100% |
| 提及次数 | `count(geo_mentions 记录)`（按提及累加，非按回答去重） | [geo_mentions](file:///d:/geo/kratos-svr/internal/data/model/geo_monitor.go#L94) 表行数 | 无 |
| 对话轮次 | `count(answer_snapshots)` 总查询回答数 | `geo_answer_snapshots` | 无 |

> ⚠️ 与盘古区别：盘古品牌可见度是加权指数（实测见 115%/233% 超过 100%），**我们用简单占比，上限 100%**，定义直观、对账清晰。`visibility_score` 留作后续可选加权优化。

**真实数据示例**（id=415 三只熊披萨）：
- 数据大盘：品牌可见度 77% / 品牌TOP3 85% / 正向情感=正 / 提及次数 1,887 / 对话轮次 2,459
- 情感倾向：无 1601(65%) / 正 823(33%) / 负 35(2%)
- 各平台分项：DeepSeek(53%/21)、豆包(65%/26)、腾讯元宝(115%/44)、文心助手(114%/46)、知乎(233%/7)

**情感倾向实现**（字段已就绪，缺判定逻辑）：
- `geo_mentions.sentiment` 字段已存在（varchar 32），但 worker 当前写死 `"neutral"`（[worker_execution.go:532/546/577](file:///d:/geo/kratos-svr/app/admin/internal/data/worker_execution.go)）
- 改动：在 `computeGeoAnalysis` 里对每条 `mention.text` 调 LLM 判定，取值 `positive`/`neutral`/`negative`（存英文，前端显示中文 无/正/负）
- 聚合查询：`SELECT sentiment, COUNT(*) FROM geo_mentions WHERE answer_snapshot_id IN (...) GROUP BY sentiment`

**数据接口**（盘古 6 个 POST，我们对应设计）：

| 盘古接口 | 区块 | 我们对应接口（建议） |
|---|---|---|
| `datareportcompanyinfo` | 顶栏 4 卡 | `GetBrandCompanyInfo` |

**布局**（已对齐有数据客户 id=415 真实截图）：
- 标题：`AI智推Max优化报表`（h1）+ 「返回品牌看板」按钮
- 客户名 + 监测周期（如「三只熊披萨 监测周期：2026-08-17至2026-08-23」）
- **周报/月报切换按钮** + **选择统计周/月下拉**（如「2026年第34周」）+ **周报下载按钮**（导出 PDF/图片）

**内容区块**：
1. **数据大盘（带环比）**：品牌可见度 % 环比 / 品牌TOP3 % 环比 / 提及次数 环比 / 收录总量 环比
   - 各平台分项：豆包/DeepSeek/腾讯元宝/AI 等（可见度%/提及次数/情感倾向）
2. **优化数据/收录数据**：累计优化天数 / 累计达标天数 / 达标剩余天数 / 词条量 / 收录总量 / 文章发布总量 / 电话收录次数 / 官网收录次数
3. **品牌推荐度**
4. **收录详情表（3 列）**：问题词条 / 总收录次数 / 周期收录次数
   - 按问题词条维度聚合（不是按回答），如「成都三只熊披萨外卖口味怎么样 | 124 | 16」
   - 申明文案：「AI大模型搜索结果千人千面，报表检测结果以系统正检测结果为准」

**关键特征**：
- **环比指标**是周月报核心价值（对比上周/上月变化）
- **按问题词条聚合**（不同于品牌看板的按回答/提及）
- **下载导出**（PDF/图片）
- 周月报共用组件，仅周期范围不同（周=7天，月=30天）

**数据来源**：复用品牌看板接口 + 新增周期聚合（`geo_sentiment_summary` 离线表 + 按周/月分桶的收录统计）。环比 = 本周期值 vs 上周期值。

## 4. 页面级权限区分设计

### 4.1 现状与差距

- **admin 后台已有 RBAC**（[admin_authorization.go](file:///d:/geo/kratos-svr/app/admin/internal/biz/admin_authorization.go) + [authorization.go](file:///d:/geo/kratos-svr/app/admin/internal/server/authorization.go)），但粒度是**服务级**（service prefix → 单一 permission code，约 13 个），read/write 不区分。
- **user 服务无 RBAC**：[http.go](file:///d:/geo/kratos-svr/app/user/internal/server/http.go) 仅 `authn.Middleware`，登录后即可访问所有 user API。
- 前端 admin 路由守卫 [access.ts](file:///d:/geo/admin/src/access.ts) + [routes.ts](file:///d:/geo/admin/config/routes.ts) 已有 `canXxx` 机制；userconsole 侧 [console-shell.tsx](file:///d:/geo/userconsole/src/components/console/console-shell.tsx) 菜单是静态硬编码，无权限过滤。

### 4.2 新增「页面权限规则」表

表名 `ent_page_grants`（遵循 `ent_` 前缀）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint PK | |
| `subject_type` | varchar(20) | `plan` / `role` / `enterprise` |
| `subject_id` | bigint | 套餐 ID / 角色 ID / 企业 ID |
| `page_key` | varchar(64) | 页面标识（`dashboard-data` / `brand-board` / `brand-record` / `infor-source` / `competitor` / `brand-report` / `business-service` 等） |
| `visible` | bool | 是否可见 |
| `created_at` / `updated_at` | timestamp | |

**三档灵活管控**（可叠加，优先级 `enterprise > role > plan`）：

| 维度 | 用途 | 示例 |
|---|---|---|
| plan | 套餐自带页面集 | 定制版自动含 `brand-board` 全套 |
| role | 角色默认页面集 | 交付人员默认含 `business-service`，企业客户默认含 `dashboard-data` |
| enterprise | 单企业例外 | 某企业临时关闭某页面 |

### 4.3 鉴权链路（双重校验）

**前端路由守卫**
- userconsole 引入 `usePageGrants` hook，登录后拉取当前用户可见 `page_key` 列表
- [console-shell.tsx](file:///d:/geo/userconsole/src/components/console/console-shell.tsx) 菜单项按 `page_key` 过滤
- 路由级 `<Guard>` 组件，无权页面重定向 403

**后端中间件**
- user 服务新增 `pageGrant` 中间件（在 `authn.Middleware` 之后）
- 参考 admin 的 `adminOperationPermission` 模式（[authorization.go:37-65](file:///d:/geo/kratos-svr/app/admin/internal/server/authorization.go)），按 operation 前缀映射 `page_key` 校验

```sql

       s.starts_at, s.expires_at
FROM enterprises e
LEFT JOIN brands b ON b.enterprise_id = e.id
LEFT JOIN ent_subscriptions s ON s.enterprise_id = e.id AND s.status='active'
WHERE e.id = ? ORDER BY s.expires_at DESC LIMIT 1;

-- 4 统计卡
SELECT
  (SELECT COUNT(*) FROM keywords WHERE enterprise_id=?) AS keyword_count,

  (SELECT COUNT(*) FROM geo_answer_snapshots s [JOIN analysis] WHERE s.enterprise_id=? AND analysis.brand_mentioned=1) AS total_inclusion,
```

**3. GetBrandDashboard**（5 聚合指标 + 当日范围）：
```sql
SELECT
  COUNT(*) AS dialogue_rounds,
  SUM(analysis.brand_mentioned) AS inclusion_count,
  ROUND(SUM(analysis.brand_mentioned)/COUNT(*)*100, 2) AS visibility_rate,
  ROUND(SUM(CASE WHEN analysis.brand_mentioned=1 AND analysis.brand_rank<=3 THEN 1 ELSE 0 END)/COUNT(*)*100, 2) AS top3_rate
FROM geo_answer_snapshots s [JOIN analysis]
WHERE s.enterprise_id=? AND DATE(s.observed_at AT TIME ZONE 'Asia/Shanghai') = CURRENT_DATE AT TIME ZONE 'Asia/Shanghai';

-- 提及次数 + 正向情感（独立查询，跨 answer_snapshot）
SELECT
  COUNT(*) AS mention_count,
  ROUND(SUM(CASE WHEN sentiment='positive' THEN 1 ELSE 0 END)/COUNT(*)*100, 2) AS positive_rate
FROM geo_mentions
WHERE answer_snapshot_id IN (
  SELECT id FROM geo_answer_snapshots WHERE enterprise_id=? AND DATE(observed_at AT TIME ZONE 'Asia/Shanghai') = CURRENT_DATE AT TIME ZONE 'Asia/Shanghai'
);

-- 各平台分项
SELECT site.platform_name,
  ROUND(SUM(analysis.brand_mentioned)/COUNT(*)*100, 2) AS visibility_rate,
  COUNT(m.id) AS mention_count
FROM geo_answer_snapshots s [JOIN analysis] JOIN geo_inclusion_sites site ON site.id=s.site_id
LEFT JOIN geo_mentions m ON m.answer_snapshot_id=s.id
WHERE s.enterprise_id=? AND ... GROUP BY site.id;
```

> ⚠️ `analysis_results` 表**无 `brand_rank` 字段**（已确认 [geo_monitor.go:108-121](file:///d:/geo/kratos-svr/internal/data/model/geo_monitor.go#L108)，字段仅 brand_mentioned/enterprise_cited/visibility_score/accuracy_score/confidence/result_json）。
>

> ```sql
> ROUND(SUM(CASE WHEN analysis.brand_mentioned=1 AND (
>   SELECT MIN(m.position) FROM geo_mentions m WHERE m.answer_snapshot_id=s.id AND m.entity_type='brand'
> ) <= 3 THEN 1 ELSE 0 END)/COUNT(*)*100, 2) AS top3_rate
> ```
> 若后续需精确的"品牌 vs 竞品排名"，再考虑新增 `analysis_results.brand_rank` 字段。

**4. GetBrandIndexMain**（3 趋势 + 情感，range 参数控制分桶）：
```sql
-- 总收录趋势（按日/月分桶，brand_mentioned=true 计数）
SELECT DATE_FORMAT(DATE_ADD(s.observed_at, INTERVAL 8 HOUR), :fmt) AS bucket,
       SUM(analysis.brand_mentioned) AS value
FROM geo_answer_snapshots s [JOIN analysis]
WHERE s.enterprise_id=? AND s.observed_at BETWEEN :from AND :to
GROUP BY bucket;

-- 品牌可见度趋势（在收录趋势基础上算占比）
SELECT bucket, ROUND(SUM(brand_mentioned)/COUNT(*)*100, 2) AS rate
FROM (...) GROUP BY bucket;

-- 提及次数趋势（按日分桶 mentions 计数）
SELECT DATE_FORMAT(DATE_ADD(m.created_at, INTERVAL 8 HOUR), :fmt) AS bucket, COUNT(*) AS value
FROM geo_mentions m
WHERE m.answer_snapshot_id IN (SELECT id FROM geo_answer_snapshots WHERE enterprise_id=? AND observed_at BETWEEN :from AND :to)
GROUP BY bucket;

-- 情感倾向 3 档
SELECT sentiment, COUNT(*) AS count, ROUND(COUNT(*)/:total*100, 2) AS rate
FROM geo_mentions
WHERE answer_snapshot_id IN (SELECT id FROM geo_answer_snapshots WHERE enterprise_id=? AND observed_at BETWEEN :from AND :to)
GROUP BY sentiment;
```

> 趋势补零：data 层用 `buildDashboardTrendSeries(range, from, to, trendMap)` 把 SQL 返回的 map 补成完整序列。
