# GEO 诊断报告指标与可追溯实施计划

> 样例：`docs/report_2026-08-24.png`
>
> 实施起点：2026-08-24

## 1. 结论

现有售前诊断已保留问题、模型配置快照、提示词、原始回答、调用响应和重试历史，可支撑基础的品牌可见度报告。要完整输出样例中的平台、竞品、信源和策略分析，还需要补齐内容事实点快照、版本化分析、实体提及、内容采纳、信源证据、指标样本血缘和报告版本。

## 2. 指标口径

| 指标 | 口径 | 无数据时的展示 |
| --- | --- | --- |
| 品牌可见度 | 提及目标品牌的有效回答数 / 有效回答数 | 0% |
| 提及次数 | 目标品牌及别名在有效回答中的实际出现次数 | 0 |
| TOP3 占比 | 目标品牌在明确推荐榜单中排名 1–3 的回答数 / 可判定排名的回答数 | 不可用 |
| 内容采纳率 | 各回答对诊断时冻结官方事实点的命中率均值 | 不可用 |
| 信源引用率 | 含至少一条提供商真实信源的回答数 / 宣称具备信源能力的有效回答数 | 不可用 |
| 情感倾向 | 目标品牌提及记录的正向/中性/负向分布，摘要显示占比最高的倾向 | 无 |
| 竞品提及率 | 提及指定竞品的有效回答数 / 有效回答数 | 0% |
| 品牌声量占比 | 目标品牌提及次数 / 所有品牌实体提及次数 | 不可用 |

“不可用”与 0 必须区分：0 表示已执行检测但没有命中；不可用表示当前模型或数据不具备该项检测能力。

## 3. 可追溯链路

```text
报告数据点 / 策略建议
  -> 报告指标 / 榜单 / 信源项
  -> 指标样本 / 发现证据
  -> 版本化分析结果
  -> 不可变模型调用结果
  -> 问题任务 + 模型快照 + 客户资料/事实点快照
  -> 原始回答 + 提示词 + 提供商请求号 + 原始响应
```

每个百分比必须能展开分子、分母样本；每个榜单实体必须能展开到提及位置和原文片段；每个信源统计必须能展开到引用 URL 及所在回答。

## 4. 数据改造

- 新增诊断事实点快照，从品牌核心价值、当前内容、产品名称、产品说明和卖点拆分生成。
- 新增版本化回答分析，保留分析规则、分析模型、提示词、原始结构化输出和失败信息。
- 新增实体提及、事实点命中、指标样本、报告榜单及信源汇总的独立表。
- 引用记录增加提供商来源编号、来源名称、摘要、引用位置、归属、验证状态和抓取时间。
- 诊断模型快照记录“接口是否返回可核验信源”。
- 报告改为追加版本，重试或重新分析时保留旧版，仅切换当前版本。
- 策略发现与指标、回答或引用建立证据关系，不只保存一段文字。

## 5. 分析方式

- 品牌和已配置竞品的提及次数、首次位置使用后端确定性规则。
- 榜单排名、未配置品牌抽取、情感和语义内容采纳使用结构化大模型分析，必须保留分析输入和原始输出，并校验证据片段确实存在于原回答。
- 信源只接收提供商 API 真实返回的引用元数据；不从大模型自行生成的 URL 或文本中推测信源。

## 6. 验收标准

- 报告顶部及每个模型均可输出品牌可见度、内容采纳率、提及次数、TOP3 占比、信源引用率和情感倾向。
- 报告可输出按模型的品牌排行、竞品提及率/提及次数、信源分布、引用详情和 TOP 信源。
- 图表数据点能展开至它的样本和原始证据。
- 无联网或无引用能力的模型显示“不可用”，不伪造 0% 结果。
- 任务重试、重新分析和报告重建不删除原始结果、分析和报告版本。
- 同一诊断的任意历史报告都能根据当时规则和关联样本复算。
