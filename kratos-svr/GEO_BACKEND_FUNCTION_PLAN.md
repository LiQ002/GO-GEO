# GEO Kratos 后端功能规划

## 1. 服务定位与边界

`kratos-svr` 下保留两个独立 app，但必须共享统一的资源命名、租户模型、任务状态和审计规范。

| app | 服务对象 | 职责 | 不应承担的职责 |
|---|---|---|---|
| `app/admin` | 平台运营人员和受控执行设备 | 平台控制面、企业运营、全局任务调度、执行节点接口、审计与系统配置 | 不用企业普通 Token；不向普通管理员返回明文平台凭据 |
| `app/user` | 企业单账号和企业授权客户端 | 企业自助管理、内容工作流、账号授权、任务发起、企业报告 | 不允许跨企业查询；不提供企业成员/RBAC、全局调度和系统密钥管理 |

建议将执行设备视为独立身份类型。即使相关接口部署在 `admin` app，也使用 `worker` audience、设备证书/短时 Token 和单独的路由权限，不能复用平台管理员 Token。

建议 API 命名空间：

```text
/api/admin/v1/...          平台运营接口
/api/admin/v1/worker/...   运营执行客户端接口（独立认证受众）
/api/user/v1/...           企业用户接口
/api/user/v1/client/...    企业授权客户端专用接口（企业身份 + 设备绑定）
```

内部共享仅限稳定的基础库、领域标识和基础设施封装。admin/user 应通过明确的仓储或内部 RPC 协作，不相互导入对方的 `internal` 包。

## 2. 统一后端规则

### 2.1 多租户

- 每个企业业务资源都必须持有 `enterprise_id`，多品牌场景同时持有 `brand_id`。
- 一个企业当前只有一个全功能账号，不设计 `enterprise_members`、企业角色或资源级成员授权。
- 预留可空 `agent_id` 表示企业归属代理商；当前不允许代理商登录或据此查询企业数据。
- `enterprise_id` 从认证上下文获得，企业端不信任请求体自行传入的租户 ID。
- 管理端跨企业查询必须检查显式权限，并记录查询或导出审计。
- 唯一索引必须包含租户维度，例如 `(enterprise_id, platform, account_id)`。
- 缓存键、对象存储路径、队列消息和日志也必须带租户范围。

### 2.2 API 契约

- Proto 是后端契约源，通过 `make all` 生成 pb.go、HTTP/gRPC 和 OpenAPI。
- 列表接口统一分页、过滤、排序和总数口径；批量接口返回逐项结果。
- 更新接口使用 FieldMask，删除默认软删除或归档。
- 所有写接口支持请求 ID；任务创建和结果上报要求幂等键。
- 时间统一存储 UTC，API 使用 RFC 3339；金额/积分使用整数最小单位。
- 错误返回稳定的 reason、可读 message、request_id 和可重试标志。

### 2.3 凭据安全

- 业务表只保存 `credential_envelope_id`，不保存可直接使用的明文 Cookie。
- 服务端采用 KMS/信封加密，数据密钥按企业或账号隔离并支持轮换。
- 执行设备只能针对已领取任务换取短时、一次性、范围受限的凭据。
- 所有换取、解密、刷新、撤销和销毁行为进入安全审计。
- 管理后台只显示账号名称、授权状态、到期时间和最后检测时间。

### 3.7 文章类型库与生成提示词管理

文章类型是企业创建文章时选择的产品模板；提示词模板和模型配置是平台内部实现。三者分别建模、通过版本关联，不能把完整提示词或模型密钥直接存进文章类型主表。

| 编号 | 优先级 | 功能 |
|---|---|---|
| ADM-ATYPE-01 | P0 | 文章类型列表，区分系统预置和平台自定义类型 |
| ADM-ATYPE-02 | P0 | 创建、复制、编辑、预览、启用、隐藏、归档自定义类型 |
| ADM-ATYPE-03 | P0 | 系统预置类型只允许启停、排序或复制为自定义类型，不允许直接覆盖原始定义 |
| ADM-ATYPE-04 | P0 | 配置名称、编码、简介、图标、排序、内容目标、目标受众、语气和推荐字数 |
| ADM-ATYPE-05 | P0 | 绑定适用投放渠道，可配置自媒体、官网、官方媒体和大 V 投稿等渠道标签 |
| ADM-ATYPE-06 | P0 | 配置文章结构：章节顺序、每节目标、必填/可选章节、字数和输出格式 |
| ADM-ATYPE-07 | P0 | 配置生成输入项：品牌、关键词、问题、产品、竞品、案例、数据、目标渠道等变量 |
| ADM-ATYPE-08 | P0 | 绑定提示词模板及版本，支持基础指令、类型指令、渠道指令和输出约束分层组合 |
| ADM-ATYPE-09 | P0 | 配置允许使用的文章编写模型、默认模型和备用模型 |
| ADM-ATYPE-10 | P0 | 配置 GEO 优化规则：问题覆盖、实体表达、事实依据、引用来源、FAQ 和摘要要求 |
| ADM-ATYPE-11 | P0 | 配置质量校验：必备章节、字数、禁用表达、事实来源、链接和重复度阈值 |
| ADM-ATYPE-12 | P0 | 发布新版本、查看版本差异、回滚；生成任务始终引用不可变版本 |
| ADM-ATYPE-13 | P1 | 使用样例变量试生成，查看最终拼装提示词、模型输出、Token、费用和耗时 |
| ADM-ATYPE-14 | P1 | 同一类型对比千问、DeepSeek、Kimi 等模型的生成结果和质量评分 |
| ADM-ATYPE-15 | P1 | 企业可见范围、套餐限制、灰度范围和企业级默认类型 |

建议首批系统预置：品牌基础介绍文、行业问题解决方案文、对比评测文、选购指南文、FAQ 问答文、案例拆解文、数据白皮书/深度报告、场景化短内容、小红书种草笔记、微博短文、事件/活动传播文。

提示词建议按以下顺序动态拼装，并记录每一层的版本：

1. 系统安全、事实性和输出规范。
2. GEO 通用优化规则。
3. 文章类型的目标、结构、语气和质量规则。
4. 目标渠道的字数、格式和平台表达规则。
5. 企业品牌、产品、禁用表达和知识库证据。
6. 本次关键词、问题、受众和用户补充要求。

## 6. 异步任务与一致性

- 创建发布/GEO 任务、扣减预占配额和写业务事件应在同一事务内完成。
- 使用 Outbox 投递队列事件，消费者按幂等键处理。
- 执行尝试与业务任务分离：一个任务可有多次尝试，但只有一个当前有效租约。
- 心跳续租必须校验 lease token、worker id、任务状态和版本。
- 结果上报先持久化原始数据，再异步分析和聚合。
- 配额建议采用“预占 -> 成功结算/按规则释放”，扣量规则由产品确认。
- 取消使用协作取消；已经发生的平台发布不能通过删除本地任务回滚。

## 7. 可观测性与运维

- API 指标：QPS、P50/P95/P99、错误 reason、数据库和缓存耗时。
- 任务指标：排队时长、执行时长、重试、租约过期、失败分类和平台成功率。
- 客户端指标：在线节点、版本、心跳、平台驱动版本、崩溃和页面选择器失败。
- 安全指标：异常登录、凭据换取、越权拒绝、批量导出和敏感配置修改。
- 所有链路关联 `request_id`、`trace_id`、`task_id`、`attempt_id`、`worker_id`。

## 8. 后端验收清单

- [ ] BE-AC-01 admin/user/worker/client 四种认证上下文不能互换。
- [ ] BE-AC-02 企业 A 无法通过 ID、过滤、导出或对象存储地址访问企业 B 数据。
- [ ] BE-AC-03 发布和 GEO 任务在并发领取、重复上报、客户端崩溃后不会产生双执行有效结果。
- [ ] BE-AC-04 原始证据不可被重新分析覆盖，分析版本和人工复核可追溯。
- [ ] BE-AC-05 明文凭据不会进入数据库普通字段、API 响应、日志或错误。
- [ ] BE-AC-06 配额预占、结算、释放和人工调整均有平衡流水。
- [ ] BE-AC-07 单个投放渠道、投稿目标、GEO 检查站点或编写模型可独立暂停，未受影响资源继续工作。
- [ ] BE-AC-08 所有敏感操作都有操作者、目标、前后值、原因、IP 和时间。
- [ ] BE-AC-09 Proto、生成 OpenAPI 和 Electron 类型在 CI 中保持一致。
- [ ] BE-AC-10 数据库迁移、备份恢复、队列积压和对象存储失败均有演练方案。
- [ ] BE-AC-11 系统预置文章类型不可被直接覆盖，历史生成任务可还原其类型、提示词、模型和输入版本。
- [ ] BE-AC-12 修改或停用文章类型/模型不会改变执行中任务的快照，新版本可试生成、灰度和回滚。

## 9. 实施顺序建议

1. 平台管理员 RBAC、企业单账号、代理商归属预留、企业/品牌和审计底座。
2. 文章类型库、提示词版本、编写模型配置和企业可用范围。
3. 文章投放渠道、GEO 检查站点及企业可用范围。
4. 需要登录态的渠道/站点账号、CredentialEnvelope 和授权客户端接口。
5. 文章生成/审核/快照、发布任务/尝试/租约、投稿回执和 worker API。
6. 关键词/问题、监测计划、GEO 查询任务和证据模型。
7. 分析聚合、看板、报告、通知和运营复核。
8. 知识库、AI 生成增强、代理商功能、商业化、开放 API 和高级优化。
