# 多平台 Puppeteer 文章发布模拟

> 该示例用于验证平台登录、会话复用、编辑器定位、键盘输入和草稿保存。它不会执行正式发布、群发、提交或下一步操作。

## 支持的平台

| 平台 | 模拟结果 | 安全策略 |
| --- | --- | --- |
| 微信公众号 | 保存草稿 | 复用公众号 token，只点击明确的草稿按钮 |
| 知乎 | 自动保存 | 填充标题和正文，等待页面显示已保存 |
| 头条号 | 保存草稿 | 只匹配“存草稿”或“保存草稿” |
| 微博 | 停留编辑页 | 进入头条文章编辑器并填充，不点击下一步或发布 |
| 百家号 | 保存草稿 | 只匹配“保存草稿”或“存草稿” |
| 小红书 | 保存草稿 | 尝试进入长文编辑器，只匹配草稿按钮 |

微博入口按照[微博官方头条文章使用指南](https://weibo.com/ttarticle/p/show?id=2309404301255450192315&mod=zwenzhang)中的网页端“头条文章”流程模拟。由于平台页面会持续改版，首次验证时应保留浏览器窗口，确认当前账号看到的编辑器结构与选择器一致。

## 运营端验证

1. 执行 `pnpm dev:operator`，登录运营端并进入“发布管理”。
2. 在“多平台文章自动发布示例”中选择平台。
3. 点击“打开平台登录”，在 Puppeteer 窗口中完成登录。
4. 返回运营端，点击填充按钮。
5. 在平台窗口中检查模拟标题、摘要和正文，以及草稿状态。

每次切换平台都会关闭上一平台的示例会话。模拟文章位于 `lib/publish-demos/media.ts`，只在 Renderer 发起演示时通过 IPC 传给主进程，不写入后端文章数据。

## 实现结构

- `components/pages/operator/MediaPublishDemo.tsx`：平台选择、会话状态和演示操作。
- `lib/services/mediaPublishDemo.ts`：Renderer 到 preload 白名单的调用封装。
- `lib/platforms/draft.ts`：五个平台复用的安全草稿驱动。
- `lib/platforms/<id>/index.ts`：每个平台的入口动作、字段选择器和草稿策略。
- `lib/platforms/wechat/publish.ts`：微信公众号专用编辑器驱动。

字段输入统一执行以下真实键盘流程：点击候选选择器、全选、退格清空、`keyboard.type()` 输入。共享驱动不会直接修改 DOM 的 `value` 或 `innerHTML`。

保存按钮使用可见文本精确匹配。配置初始化时会拒绝包含“发布”“群发”“发送”“提交”或“下一步”的动作；如果找不到安全草稿按钮，自动化会报错并停留在浏览器页面。

## 选择器维护

平台改版后，先在可见浏览器中确认失败字段，再只调整对应 `lib/platforms/<id>/index.ts` 中的候选选择器。不要添加宽泛的主按钮选择器，也不要把正式发布动作混入草稿模拟驱动。

修改后至少执行：

```bash
pnpm typecheck
pnpm test
pnpm build:electron
```
