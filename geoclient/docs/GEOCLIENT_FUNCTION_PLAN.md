# GeoClient 双客户端功能规划

> 文档状态：待产品与技术核对
> 更新日期：2026-07-18
> 关联总规划：[GEO 系统总体规划](../../GEO_SYSTEM_PLAN.md)

## 1. 产品边界

`geoclient` 使用同一套 Electron + Next.js + TypeScript 代码生成两个安装包，但两者是不同产品身份：

| 构建模式 | 面向用户 | 核心职责 |
|---|---|---|
| `operator` | 平台内部运营执行人员 | 查看企业待办，领取租约，执行自媒体发布、官方媒体/大 V 投稿和 GEO 收录查询，上报结果与证据 |
| `client` | 企业单账号 | 登录并完成需要企业登录态的投放渠道/GEO 检查站点授权，管理授权健康状态和设备安全 |

两个安装包必须使用不同 appId、产品名、本地数据目录、Renderer 页面、Token audience 和 API 权限。企业授权端不能获得运营任务池，运营执行端不能使用企业普通接口随意修改内容。

## 5. Electron 技术与安全边界

### 5.1 Renderer

- 保持 `sandbox: true`、`contextIsolation: true`、`nodeIntegration: false`。
- 只保存展示偏好和非敏感用户摘要；访问 Token、Cookie、密钥不进入 localStorage。
- client/operator 路由和业务代码在构建期裁剪，并在构建后校验模式标记。
- 所有 API 路径来自 Kratos 生成 OpenAPI 类型，不维护未校验字符串路径。

### 5.2 Preload 与 IPC

- contextBridge 采用最小白名单，按授权、发布、GEO 查询、窗口和诊断拆分。
- IPC 参数进行运行时校验，限制平台 ID、URL、正文/凭据大小和文件路径。
- 长任务返回 job ID，通过事件订阅进度；支持取消和窗口销毁清理。
- 不提供任意 shell、任意文件读写、任意 URL 打开或任意 JavaScript 执行接口。

### 5.3 主进程与浏览器

- 每次授权/任务使用隔离会话，结束后统一清理页面、上下文和临时文件。
- 只允许 HTTPS 外链；权限请求默认拒绝，只对明确场景按域名临时放行。
- 平台驱动声明登录域名、发布/查询地址、Cookie 白名单和能力版本。
- 浏览器页面内容是不可信输入，不能让页面数据控制本地路径或命令。
- 正式包只使用随包签名的 Chromium 与驱动资源，不静默回退未知浏览器。

### 5.4 跨设备凭据

当前版本使用共享 AES-256-GCM：用户端在 Electron 主进程生成 `aes:v2:` 密文，后端按企业和平台账号保存不透明密文，运营端领取发布租约后使用相同密钥解密。用户端与运营端必须配置相同的 `COOKIE_AES_KEY`，未配置时均使用内置兼容密钥。

本版本约束：

1. 每个企业的每个平台只维护一个授权账号，不提供多账号选择。
2. 后端只接受 `aes:v2:`，历史 `safe:v1:`、旧 `v1:` 和明文授权需要重新授权。
3. 明文只在 Electron 主进程内存中短时存在，不进入 Renderer、服务端字段或日志。

后续安全版本升级为 KMS/公钥信封加密：

1. 企业授权客户端将凭据使用随机数据密钥加密。
2. 数据密钥由服务端 KMS/企业公钥封装，服务端保存密钥信封。
3. 运营客户端领取有效任务后获取短时、范围受限的解封授权。
4. 明文只在 Electron 主进程任务内存中短时存在，任务结束主动清理。
5. 密钥轮换、设备吊销和账号撤销后，旧授权不能继续使用。

## 6. 本地数据与离线策略

| 数据 | 是否可持久化 | 建议 |
|---|---:|---|
| UI 偏好、窗口位置 | 是 | 普通本地配置 |
| 用户/企业展示摘要 | 是 | 最小化保存，退出时清理 |
| Access/Refresh Token | 是 | 仅系统安全存储，不进 Renderer |
| 平台明文 Cookie | 否 | 任务内存短时使用 |
| 加密凭据/信封 | 有条件 | 仅为待上传恢复，上传成功立即清理 |
| 待上报执行结果 | 是 | 加密、带幂等键、成功后删除 |
| 截图和诊断包 | 有条件 | 限时保存、脱敏、可由用户查看并删除 |

离线时不领取新任务；已开始任务应继续心跳重试并在无法确认租约时停止可能造成副作用的后续步骤。已经产生的平台结果可加密缓存并在恢复网络后幂等补报。

## 7. 平台适配器验收矩阵

每个投放渠道或 GEO 检查站点都必须单独记录以下能力，不能只标记“已支持”。适配器类型分为 `self_media`、`official_media`、`kol` 和 `inclusion_site`：

| 能力项 | 验收内容 |
|---|---|
| 登录授权 | 登录成功检测、验证码/二次验证、白名单采集、恢复会话 |
| 账号识别 | 账号 ID、名称、头像、有效期和多账号区分 |
| 自媒体发布 | 标题、正文、图片、封面、摘要、标签、草稿、正式发布 |
| 官方媒体投稿 | 投稿入口/邮箱、栏目、稿件格式、回执、采用/拒绝和跟进 |
| 大 V 投稿 | 平台账号、合作要求、联系方式、费用确认、回执和跟进 |
| 结果确认 | 平台内容 ID、URL、投稿回执、采用状态、成功页面和截图 |
| GEO 查询 | 检查站点新会话、提问、流式完成、回答原文、引用、截图 |
| 异常处理 | 过期、风控、限流、页面变化、网络错误和不可重试错误 |
| 平台限制 | 字数、图片、频率、地区、账号等级和使用政策 |
| 自动化测试 | 选择器单测、离线页面样本、受控真实环境冒烟测试 |

平台上线状态建议为：`experimental -> internal -> canary -> stable -> paused -> retired`。
